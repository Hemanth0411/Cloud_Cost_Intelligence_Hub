## `query/scoped.py` ★

The security boundary. Everything else is plumbing.

| Export | Purpose |
|---|---|
| `GRANT_PREDICATE` | the SQL `EXISTS` clause — module constant so it is testable and reviewable in isolation |
| `Principal` | `user_id`, `email`, `role`; built from the verified token only |
| `Filters` | date range, provider/account/service, metric, tax-and-credits toggle |
| `series(principal, filters, grain)` | cost over time (FR-18) |
| `by_dimension(principal, filters, dimension)` | breakdown (FR-19) |
| `compare(principal, current, previous, dimension)` | period-over-period with absolute **and** percent delta (FR-21, FR-22) |
| `visible_accounts(principal)` | scoped dropdown contents (FR-9) |
| `visible_services(principal, provider, account)` | scoped dropdown contents |

### Why no ORM

The grant predicate decides who sees whose spend. Written as SQL it can be
read, reviewed and diffed directly. Generated by an ORM it would have to be
inferred from query logs. For the one piece of code that must be obviously
correct, explicit SQL is the safer choice.

### Injection safety

`GROUP BY` targets and time grains are interpolated into SQL, so they come
from the `DIMENSIONS` and `GRAINS` allowlists — never from caller input.
Every value is a bound parameter.

## `ingest/`

### The port

```python
class CostSource(Protocol):
    name: str
    def fetch(self, *, account_id, start, end) -> Iterable[CostRow]: ...
```

`CostRow` field names follow FOCUS, so `focus_export.py` later requires no
translation layer (NFR-20).

| Adapter | Source | Status |
|---|---|---|
| `dev_seed` | generated rows so the backend can be built without AWS credentials | built |
| `cost_explorer` | `ce:GetCostAndUsage`, `DAILY`, grouped by `SERVICE` + `REGION` | built |
| `azure_cm` | Azure Cost Management Query API | built, **unverified live** |
| `focus_export` | Athena over FOCUS 1.2 export | TODO-15 |

Adding a provider is one new class plus one entry in `sources.py` (NFR-17).
`runner.py`, `cli.py` and the Lambda handler never change.

### Two different things called "mock"

Keep these separate; conflating them is how a demo ends up proving nothing.

| | Purpose | Lives in |
|---|---|---|
| **`dev_seed`** | lets the backend be developed with no AWS credentials | this module, database |
| **Showcase fixtures** | shows what many AWS + Azure accounts *look like* | **frontend only** — see [06-frontend.md](06-frontend.md) |

Showcase data deliberately never enters the database. It is a frontend
fixture matching the API envelope, so it is removable by deleting a file
rather than by a migration and a data cleanup — and there is no path by
which it can be served as real.

### `azure_cm` notes

Same port, no schema change: `provider='azure'`, `account_id` holds the
subscription (or billing account) id, and the columns are already
FOCUS-aligned.

| Concern | Detail |
|---|---|
| Auth | Entra app registration: tenant id, client id, client secret. Azure has **no cross-cloud equivalent of `AssumeRole`**, so a long-lived secret is unavoidable — it goes in Secrets Manager, rotation is TODO-3 |
| Role needed | **Cost Management Reader** at subscription or billing-account scope (*Contributor* only if creating exports) |
| Response shape | parallel `columns` / `rows` arrays. The column **order is not contractual** — it shifts with the grouping requested — so values are mapped by NAME. A positional read silently swaps cost and date; `test_columns_are_mapped_by_name_not_position` pins it. |
| Date format | daily granularity returns `UsageDate` as the integer `20261010`, not a date string |
| Agreement split | EA returns `PreTaxCost` where MCA returns `Cost`; both accepted |
| Multi-tenant | one app registration per tenant, one `cloud_connections` row each |
| Testability | **built but not verified** without a subscription. 20 unit tests cover parsing and transport through a mock httpx client, so the request shape and pagination are real; the live path is not. Say so plainly. |

### Cost Explorer specifics

- Endpoint is **us-east-1 only**, regardless of where anything else runs
- Costs $0.01 per request — negligible, but the reason we do not poll
- ~14 months of history available
- `GroupBy` accepts at most **2** dimensions, so region needs a second call
  or is left unfilled in the rollup
- `LINKED_ACCOUNT` returns one value in a standalone account; multi-account
  comes from iterating connections, not from one grouped call

## `anomaly/`

```python
class Detector(Protocol):
    name: str
    def detect(self, series: list[tuple[date, Decimal]]) -> list[Finding]: ...
```

`mad.py` — rolling median plus median absolute deviation, then classify
`step` / `spike` / `creep`. Robust to outliers and explainable.

Deliberately **not** Prophet: the dependency tree is painful in a Lambda zip,
and a forecast band is harder to explain than "this is 6 MADs above the
28-day median".

`aws_cad.py` (future) consumes AWS Cost Anomaly Detection findings over SNS —
free, managed, already tuned for cost data.

## `api/`

FastAPI on a Lambda Function URL — no API Gateway, one less component.

`deps.py` is the only place a `Principal` is constructed:

1. verify the JWT **signature** against Cognito's JWKS
2. verify issuer, audience and expiry
3. verify the email domain is `chryselys.com`
4. look up the user; reject `disabled`
5. return `Principal(user_id, email, role)`

Step 1 is called out because skipping signature verification — decoding the
token without checking it — is the classic failure here, and it is an open
finding in the DFIQ RBAC audit. Do not inherit it.

## Conventions

- Files ≤300 lines (NFR-18)
- `from __future__ import annotations` in every module
- Audit columns on every table; `created_by` always supplied explicitly
- Money as `Decimal` in Python, `numeric` in SQL — never float
- `audit.log()` takes a cursor, not a connection, so the entry shares the
  caller's transaction
- Protocols for the three swap points; no inheritance hierarchies
